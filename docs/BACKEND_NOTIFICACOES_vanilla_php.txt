================================================================================
1. VISAO GERAL E POR QUE PERSISTIR NO BACKEND
================================================================================
- O app precisa de historico, badge de nao-lidas, e acesso multi-unidade.
  Se a notificacao existir so no app (memoria), ela se perde ao desinstalar,
  trocar de unidade (CondominioContext) ou fazer logout (AuthContext).
- Backend e fonte da verdade. App faz polling (60s) + pull-to-refresh
  e exibe toast/banner. Push Expo nativo e Fase 2 opcional.
- Toda notificacao nasce no backend via criarNotificacao() - nunca o app
  cria direto no banco. App apenas LE e MARCA COMO LIDA.

Fluxo padrao para QUALQUER modulo:
  Evento de dominio (ex: INSERT entregas, vencimento fatura, facial)
    -> PHP chama criarNotificacao($pdo, [...])
    -> INSERT tbl_notificacao (respeita preferencia do usuario)
    -> (opcional Fase 2) dispara Expo Push para tokens da unidade
    -> App na proxima polling exibe badge + lista + toast sonoro

Categorias padrao (nao crie fora deste ENUM sem migrar app):
  encomenda, fatura, acesso, portao, veiculo, sistema

// helpers/response.php - helpers de resposta JSON + CORS vanilla

function setCorsHeaders() {
    // Ajuste origin em producao para dominio do app/web
    header('Access-Control-Allow-Origin: *');
    header('Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS');
    header('Access-Control-Allow-Headers: Content-Type, Authorization, X-Requested-With');
    header('Access-Control-Allow-Credentials: true');
    if ($_SERVER['REQUEST_METHOD'] === 'OPTIONS') {
        http_response_code(204);
        exit;
    }
}

function jsonResponse($data, $httpCode = 200) {
    http_response_code($httpCode);
    header('Content-Type: application/json; charset=utf-8');
    echo json_encode($data, JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES);
    exit;
}

function jsonError($message, $httpCode = 400, $extra = []) {
    $payload = array_merge(['status' => 'error', 'message' => $message], $extra);
    jsonResponse($payload, $httpCode);
}

function jsonSuccess($message = 'OK', $extra = [], $httpCode = 200) {
    $payload = array_merge(['status' => 'success', 'message' => $message], $extra);
    jsonResponse($payload, $httpCode);
}

function getJsonInput() {
    $raw = file_get_contents('php://input');
    if (empty($raw)) return [];
    $data = json_decode($raw, true);
    if (json_last_error() !== JSON_ERROR_NONE) {
        // Tenta fallback form-urlencoded (login2.php faz assim)
        parse_str($raw, $fallback);
        return $fallback ?: [];
    }
    return is_array($data) ? $data : [];
}

function sanitizeString($v, $maxLen = 500) {
    if (!is_string($v)) return '';
    $v = trim($v);
    if (mb_strlen($v) > $maxLen) $v = mb_substr($v, 0, $maxLen);
    return $v;
}
?>

// helpers/auth_helper.php - extrai usuario do token (Bearer)
// Adaptar conforme seu login2.php. Hoje o app usa Bearer token em api.js
// Se ainda usa session_/cookie, adapte para ler $_COOKIE ou $_SESSION

function getBearerToken() {
    $header = null;
    if (isset($_SERVER['HTTP_AUTHORIZATION'])) {
        $header = $_SERVER['HTTP_AUTHORIZATION'];
    } elseif (isset($_SERVER['REDIRECT_HTTP_AUTHORIZATION'])) {
        $header = $_SERVER['REDIRECT_HTTP_AUTHORIZATION'];
    } elseif (function_exists('apache_request_headers')) {
        $h = apache_request_headers();
        $header = $h['Authorization'] ?? $h['authorization'] ?? null;
    }
    if ($header && preg_match('/Bearer\s+(.+)/i', $header, $m)) {
        return trim($m[1]);
    }
    // Fallback: token via query/body (para testes curl)
    if (!empty($_GET['token'])) return $_GET['token'];
    if (!empty($_POST['token'])) return $_POST['token'];
    return null;
}

// Retorna array com id_tbl_condomino / id_tbl_usuario / id_tbl_unidade se conseguir resolver
// Se seu sistema ainda nao tem JWT, troque esta funcao para consultar tbl_condomino por token
function getAuthUser(PDO $pdo) {
    $token = getBearerToken();
    if (!$token) return null;

    // TENTATIVA 1: token salvo em tbl_condomino.token (legado one_startup.sql)
    $stmt = $pdo->prepare("SELECT id_tbl_condomino, id_tbl_condominio, nome, cpf FROM tbl_condomino WHERE token = :t LIMIT 1");
    $stmt->execute([':t' => $token]);
    $row = $stmt->fetch();
    if ($row) {
        return [
            'id_tbl_condomino' => $row['id_tbl_condomino'],
            'id_tbl_condominio' => $row['id_tbl_condominio'],
            'nome' => $row['nome'],
            'cpf' => $row['cpf'],
            'token' => $token
        ];
    }

    // TENTATIVA 2: session_ fallback (app gera session_ quando backend nao retorna token)
    // Neste caso, tente extrair id do proprio token: session_{timestamp}_{id_condomino}
    if (strpos($token, 'session_') === 0) {
        $parts = explode('_', $token);
        $id = end($parts);
        if (is_numeric($id)) {
            $stmt = $pdo->prepare("SELECT id_tbl_condomino, id_tbl_condominio, nome, cpf FROM tbl_condomino WHERE id_tbl_condomino = :id LIMIT 1");
            $stmt->execute([':id' => (int)$id]);
            $row = $stmt->fetch();
            if ($row) {
                $row['token'] = $token;
                return $row;
            }
        }
    }

    // TENTATIVA 3: JWT real (se migrar no futuro) - decodificar sem validar assinatura por enquanto
    // Descomente se usar JWT:
    // $parts = explode('.', $token); if(count($parts)==3){ $payload=json_decode(base64_decode($parts[1]),true); ... }

    return null;
}

// helpers/notificacao_helper.php - FUNCAO CENTRAL que todo modulo deve chamar
// Vanilla PHP, PDO, sem dependencias

require_once __DIR__ . '/response.php';

/**
 * Cria notificacao no banco respeitando preferencias do destinatario.
 *
 * @param PDO $pdo
 * @param array $dados [
 *   'id_tbl_condominio' => int|null,
 *   'id_tbl_unidade'    => int|null,      // obrigatorio para filtrar por unidade no app
 *   'id_tbl_condomino'  => int|null,      // null = broadcast para todos da unidade
 *   'id_tbl_usuario'    => int|null,
 *   'categoria'         => 'encomenda'|'fatura'|'acesso'|'portao'|'veiculo'|'sistema',
 *   'tipo'              => string,        // ex: encomenda_created
 *   'titulo'            => string,
 *   'descricao'         => string,
 *   'prioridade'        => 'baixa'|'media'|'alta'|'critica' (default media),
 *   'deep_link_screen'  => string|null,   // ex: Encomendas
 *   'deep_link_params'  => array|null,    // ex: ['codigoHash'=>'abc']
 *   'metadata'          => array|null,
 *   'cod_notificacao'   => string|null
 * ]
 * @return int|false id inserido ou false se bloqueado por preferencia
 */
function criarNotificacao(PDO $pdo, array $dados) {
    $categoriasValidas = ['encomenda','fatura','acesso','portao','veiculo','sistema'];
    $prioridadesValidas = ['baixa','media','alta','critica'];

    $categoria = strtolower(trim($dados['categoria'] ?? ''));
    if (!in_array($categoria, $categoriasValidas, true)) {
        error_log("[criarNotificacao] categoria invalida: $categoria");
        return false;
    }
    $tipo = sanitizeString($dados['tipo'] ?? $categoria, 60);
    $titulo = sanitizeString($dados['titulo'] ?? '', 150);
    $descricao = sanitizeString($dados['descricao'] ?? '', 500);
    if ($titulo === '' || $descricao === '') {
        error_log("[criarNotificacao] titulo/descricao vazios");
        return false;
    }
    $prioridade = in_array($dados['prioridade'] ?? 'media', $prioridadesValidas, true) ? $dados['prioridade'] : 'media';

    $idCondominio = isset($dados['id_tbl_condominio']) ? (int)$dados['id_tbl_condominio'] : null;
    $idUnidade    = isset($dados['id_tbl_unidade']) ? (int)$dados['id_tbl_unidade'] : null;
    $idCondomino  = isset($dados['id_tbl_condomino']) ? (int)$dados['id_tbl_condomino'] : null;
    $idUsuario    = isset($dados['id_tbl_usuario']) ? (int)$dados['id_tbl_usuario'] : null;

    // Se for para condomino especifico, respeitar preferencia
    if ($idCondomino) {
        $stmt = $pdo->prepare("SELECT habilitado FROM tbl_notificacao_preferencia WHERE id_tbl_condomino = :c AND categoria = :cat LIMIT 1");
        $stmt->execute([':c' => $idCondomino, ':cat' => $categoria]);
        $pref = $stmt->fetch();
        if ($pref && (int)$pref['habilitado'] === 0) {
            // Usuario desativou esta categoria
            return false;
        }
    }

    // Se broadcast (idCondomino null) mas tem idUnidade, expandir para todos da unidade
    // Para evitar spam, aqui inserimos 1 linha com id_tbl_condomino NULL e app filtra por unidade
    // Alternativa: descomentar bloco abaixo para criar 1 linha por morador da unidade
    /*
    if (!$idCondomino && $idUnidade) {
        $stmt = $pdo->prepare("SELECT id_tbl_condomino FROM tbl_condomino WHERE id_tbl_condominio = :cond AND unidade = :unid");
        // adapte query conforme sua relacao unidade-condomino
    }
    */

    $deepScreen = isset($dados['deep_link_screen']) ? sanitizeString($dados['deep_link_screen'], 60) : null;
    $deepParams = isset($dados['deep_link_params']) && is_array($dados['deep_link_params']) ? json_encode($dados['deep_link_params'], JSON_UNESCAPED_UNICODE) : null;
    $metadata   = isset($dados['metadata']) && is_array($dados['metadata']) ? json_encode($dados['metadata'], JSON_UNESCAPED_UNICODE) : null;
    $codNotif   = isset($dados['cod_notificacao']) ? sanitizeString($dados['cod_notificacao'], 30) : null;
    if (!$codNotif) {
        $codNotif = strtoupper(substr($categoria,0,3)) . '-' . date('Ymd') . '-' . substr(uniqid(), -4);
    }

    $sql = "INSERT INTO tbl_notificacao
        (id_tbl_condominio, id_tbl_unidade, id_tbl_condomino, id_tbl_usuario, categoria, tipo, titulo, descricao, prioridade, status, cod_notificacao, deep_link_screen, deep_link_params, metadata, data_criacao)
        VALUES (:cond, :unid, :condomino, :usuario, :cat, :tipo, :tit, :desc, :prio, 'unread', :cod, :screen, :params, :meta, NOW())";

    $stmt = $pdo->prepare($sql);
    $stmt->execute([
        ':cond'     => $idCondominio,
        ':unid'     => $idUnidade,
        ':condomino'=> $idCondomino,
        ':usuario'  => $idUsuario,
        ':cat'      => $categoria,
        ':tipo'     => $tipo,
        ':tit'      => $titulo,
        ':desc'     => $descricao,
        ':prio'     => $prioridade,
        ':cod'      => $codNotif,
        ':screen'   => $deepScreen,
        ':params'   => $deepParams,
        ':meta'     => $metadata,
    ]);

    $id = (int)$pdo->lastInsertId();

    // Fase 2: enviar push Expo se houver tokens (secao 17)
    // enviarPushParaUnidade($pdo, $idUnidade, $titulo, $descricao, ['id'=>$id,'categoria'=>$categoria,'tipo'=>$tipo]);

    return $id;
}

/**
 * Envia push via Expo Push Service (Fase 2 - opcional no MVP)
 * Requer tokens ExponentPushToken[...] salvos em tbl_push_token
 */
function enviarPushParaUnidade(PDO $pdo, $idUnidade, $titulo, $corpo, array $data = []) {
    if (!$idUnidade) return;
    $stmt = $pdo->prepare("SELECT token FROM tbl_push_token WHERE id_tbl_unidade = :u AND token LIKE 'ExponentPushToken%'");
    $stmt->execute([':u' => (int)$idUnidade]);
    $tokens = $stmt->fetchAll(PDO::FETCH_COLUMN);
    if (!$tokens) return;

    $messages = [];
    foreach ($tokens as $t) {
        $messages[] = [
            'to' => $t,
            'title' => $titulo,
            'body' => $corpo,
            'data' => $data,
            'sound' => 'default',
            'priority' => 'high',
            'channelId' => 'default'
        ];
    }

    $ch = curl_init('https://exp.host/--/api/v2/push/send');
    curl_setopt_array($ch, [
        CURLOPT_POST => true,
        CURLOPT_HTTPHEADER => ['Content-Type: application/json', 'Accept: application/json'],
        CURLOPT_POSTFIELDS => json_encode($messages, JSON_UNESCAPED_UNICODE),
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_TIMEOUT => 8,
    ]);
    $resp = curl_exec($ch);
    $err = curl_error($ch);
    curl_close($ch);
    if ($err) error_log("[push] erro curl: $err");
    else error_log("[push] resp: $resp");
}

function criarSeNaoExiste(PDO $pdo, $fatura, $tipo) {
    // Evita duplicar notificacao do mesmo tipo para mesma fatura no mesmo dia
    $stmt=$pdo->prepare("SELECT id FROM tbl_notificacao WHERE categoria='fatura' AND tipo=:t AND JSON_EXTRACT(metadata,'$.id_fatura')=:fid AND DATE(data_criacao)=CURDATE() LIMIT 1");
    // Fallback TEXT: WHERE metadata LIKE :like
    // Ajuste conforme seu MySQL
    try {
        $stmt->execute([':t'=>$tipo, ':fid'=>$fatura['id_tbl_fatura']]);
        if($stmt->fetch()) return false;
    } catch(Exception $e){
        $stmt=$pdo->prepare("SELECT id FROM tbl_notificacao WHERE categoria='fatura' AND tipo=:t AND metadata LIKE :like AND DATE(data_criacao)=CURDATE() LIMIT 1");
        $stmt->execute([':t'=>$tipo, ':like'=>'%"id_fatura":'.$fatura['id_tbl_fatura'].'%']);
        if($stmt->fetch()) return false;
    }
    return true;
}

17. RECOMENDACOES OBRIGATORIAS PARA FUTURAS ALTERACOES FUNCIONAREM
================================================================================
LEIA COM ATENCAO - Repasse esta secao para quem for alterar PHP/Banco/App:

[OBRIGATORIO - BANCO]
1. NUNCA renomeie colunas de tbl_notificacao sem migrar app. O app espera:
   id, cod_notificacao, categoria, tipo, titulo, descricao, prioridade, status,
   deep_link_screen, deep_link_params, metadata, data_criacao, data_leitura
   Se renomear, quebre a API morador/notificacoes.php e o app (NotificacoesScreen).
2. Ao adicionar nova categoria, adicione no ENUM de tbl_notificacao E no
   array $categoriasValidas de notificacao_helper.php E no app
   src/constants/notifications.js e src/utils/notificationMapper.js
   Caso contrario o INSERT sera bloqueado (return false).
3. Nao remova indices idx_unidade_status_data - sem ele a listagem paginada
   fica lenta com 10k+ notificacoes.
4. Se trocar JSON por TEXT (MySQL 5.6), ajuste TODOS os json_encode/json_decode
   e as queries de cron que usam JSON_EXTRACT para LIKE.
5. Ao criar tbl_fatura real, mantenha colunas id_tbl_unidade, id_tbl_condominio,
   vencimento (DATE), status, valor. O cron depende disso.
6. Sempre que criar nova tabela que gera notificacao (ex: tbl_reserva),
   adicione id_tbl_unidade para vincular notificacao a unidade correta.

[OBRIGATORIO - PHP]
7. Todo INSERT que deve gerar notificacao DEVE chamar criarNotificacao()
   imediatamente apos o INSERT principal, DENTRO da mesma transacao se possivel,
   mas NAO deixe falha de notificacao quebrar o fluxo principal (try/catch).
   Exemplo: entrega criada deve ser salva mesmo se notificacao falhar.
8. Nunca faca echo/print antes de jsonResponse() - quebra JSON do app (api.js).
9. Sempre use prepared statements (PDO prepare) - todos os exemplos ja usam.
   Nunca concatene $_GET/$_POST direto na SQL.
10. Mantenha setCorsHeaders() e getJsonInput() em todos os endpoints morador/api.
    O app envia JSON e Bearer token (api.js interceptor).
11. Ao adicionar novo endpoint, adicione-o na lista de CORS e valide
    getAuthUser() se for rota privada. Rotas publicas (cron) devem validar
    cron_token.
12. Nao altere o formato de resposta de morador/notificacoes.php:
    {status:'success', notificacoes:[], total, unreadCount, page, limit}
    O app faz fallback Array.isArray(response.data) vs response.data.notificacoes
    (NotificacoesScreen.js:31). Mudar quebra app em producao.
13. Endpoints de escrita devem aceitar OPTIONS (preflight) - setCorsHeaders ja faz.
14. Logue erros com error_log() e retorne mensagem generica ao app (LGPD).
    Nunca exponha stack trace ou SQL no jsonError.
15. Se migrar para JWT real, atualize helpers/auth_helper.php getAuthUser()
    para validar assinatura. Enquanto usar token de tbl_condomino, mantenha
    fallback session_.

[OBRIGATORIO - APP (para devs mobile)]
16. Novos modulos NUNCA devem chamar api.get('/notificacoes') direto.
    Use NotificationContext (src/contexts/NotificationContext.js) - ele centraliza
    polling 60s, cache e badge. Ver docs/ARCHITECTURE.md.
17. Ao criar nova categoria, adicione icone/cor em notificationMapper.js e
    filtro em NotificacoesScreen + badge em DashboardScreen.
18. Deep links: sempre envie deep_link_screen existente em App.js Stack
    (Login, Home, MeusVeiculos, Notificacoes, Portoes, etc). Se screen nao
    existir, o app ignora e abre Notificacoes.
19. Preferencias: app salva em tbl_notificacao_preferencia via
    morador/notificacao_preferencias.php e respeita no helper PHP antes de INSERT.
    Nao filtre no app - filtre no backend para economizar polling.
20. Som/vibracao: canal Android "default" deve ter sound default e vibration.
    iOS usa sound default. Nao crie canais novos sem atualizar pushNotifications.js.

[OBRIGATORIO - DEPLOY]
21. Ao subir novo PHP, teste com curl (secao 18) antes de liberar app.
22. Sempre que alterar ENUM, rode ALTER TABLE antes de subir PHP novo.
23. Versionamento: mantenha runtimeVersion em app.json compativel; se mudar
    contrato de notificacao, incremente e force update.

[RECOMENDADO - OPERACIONAL]
24. Limpeza: crie rotina mensal DELETE FROM tbl_notificacao WHERE status='read'
    AND data_leitura < DATE_SUB(NOW(), INTERVAL 90 DAY) para nao inflar banco.
25. Monitoramento: ative error_log e verifique cron log diariamente.
26. Backup antes de qualquer ALTER TABLE.
27. Documente novo tipo em docs/ANALISE_PRODUCAO.md ou crie docs/NOTIFICACOES.md

20. SEGURANCA, LGPD E PERFORMANCE
================================================================================
- LGPD: notificacao contem dados pessoais (nome dependente, unidade). So exiba
  para dono da unidade (filtro id_tbl_unidade + id_tbl_condomino). Nunca retorne
  notificacoes de outra unidade.
- Consentimento push: so registre tbl_push_token apos usuario aceitar permissao
  no app (expo-notifications). Ofereca opt-out por categoria em
  notificacao_preferencias.php (ja implementado).
- Nao logue CPF/token em error_log - logger.js do app ja sanitiza.
- Indices ja criados garantem listagem <100ms com 50k linhas. Se crescer muito,
  particione por id_tbl_condominio ou arquive lidas antigas.
- Rate limit: adicione throttle em notificacao_read.php se sofrer spam (ex: 10 req/s por IP).
- HTTPS obrigatorio (app.json android.usesCleartextTraffic=false).

21. TROUBLESHOOTING
================================================================================
- Erro "categoria invalida" no error_log -> voce enviou categoria fora do ENUM.
  Ver secao 17 item 2.
- Lista vazia mas tem dados no banco -> verifique id_tbl_unidade enviado pelo app
  (CondominioContext.selectedCondominio.id_tbl_unidade) vs coluna id_tbl_unidade.
  Use broadcast: id_tbl_unidade IS NULL aparece para todos da unidade.
- JSON mal formado -> verifique se PHP deu echo antes de jsonResponse (BOM, warning).
  Ative display_errors=Off em producao.
- CORS bloqueado no app web -> verifique setCorsHeaders() e OPTIONS 204.
- Cron nao cria notificacao -> verifique vencimento DATE vs DATETIME, timezone
  (date_default_timezone_set('America/Sao_Paulo')), e se fatura status='aberta'.
- Push nao chega (Fase 2) -> verifique token formato ExponentPushToken e
  se expo-server-sdk responde 200. Log em error_log.
